# 文档状态：历史 M6 CSS Editor 设计稿

> 本文记录的是 M6 CSS Editor Experience 阶段的历史实现方案，不是当前 M6A production contract。
>
> 当前平台已经迁移到 Workspace/Draft + Exercise v2 + IndexedDB v2 + Browser Runtime。本文中的 `useExerciseProgress.updateCss`、CSS-only React state、禁止 HTML editor 等描述只用于解释当时的 M6 设计背景，不得作为当前实现依据。
>
> 当前约束请以 `AGENTS.md`、`README.md`、`docs/功能文档/前端indexdb封装方案.md` 与 M6A 任务计划为准。当前正式课程仍是 CSS Lab，但 Workspace 支持 content 声明 editable HTML；Browser Runtime 当前只执行 HTML + CSS，尚未实现 JavaScript/TypeScript Runtime。

# 6. React lifecycle

CodeMirror 是 external imperative system。

使用 Effect：

```text
mount:
  new EditorView(...)

cleanup:
  view.destroy()
```

代码必须能正确承受 React Strict Mode 的 setup → cleanup → setup。

保留现有 initial-value snapshot 思路，不要因为 `value` 改变而重新创建 EditorView。

不要使用 `useMemo/useCallback` 做没有实际意义的 premature optimization。

如果 callback 是在 mount Effect 中安装到 CodeMirror 的长生命周期 listener，并需要读取最新 props，可以使用 React 19.2 `useEffectEvent`。

典型：

```ts
const emitChange = useEffectEvent((nextValue: string) => {
  onChange(nextValue);
});
```

不要把 `useEffectEvent` 当成普通事件 handler 或 `useCallback` 的替代品。

# 7. External React → CodeMirror synchronization

当前 `externalUpdateRef` 应替换成 CodeMirror transaction metadata。

在：

```text
src/features/exercise/lib/editor/css-editor-transactions.ts
```

定义类似：

```ts
export const externalSyncAnnotation =
  Annotation.define<boolean>();
```

当 React `value` 与 CodeMirror 当前 document 不同时：

```ts
view.dispatch({
  changes: {
    from: 0,
    to: view.state.doc.length,
    insert: value,
  },
  annotations: [
    externalSyncAnnotation.of(true),
    Transaction.addToHistory.of(false),
  ],
});
```

要求：

1. persisted IndexedDB hydration 不产生 undo entry
2. external synchronization 不重新触发 React `onChange`
3. 普通用户编辑仍正常触发 `onChange`

Update listener 中检查：

```text
docChanged
+
transaction 是否为 external sync
```

不要继续依赖 mutable boolean `externalUpdateRef`。

# 12. Format race safety

Format 是 async。

开始 format 时捕获：

```ts
const sourceDoc = view.state.doc;
const source = sourceDoc.toString();
const cursorOffset = view.state.selection.main.head;
```

Prettier resolve 后：

第一层检查：

```text
当前 EditorView 是否还是同一个 mounted view
```

即类似：

```ts
editorViewRef.current === view
```

否则：

```text
status = cancelled
```

第二层检查：

```ts
view.state.doc === sourceDoc
```

利用 CodeMirror immutable document identity 判断期间是否发生 document change。

如果不同：

```text
status = stale
```

绝对禁止旧 formatter result 覆盖期间用户的新输入。

不要只依赖 formatted source string equality，因为用户可能：

```text
修改
→ 又改回原字符串
```

但这仍然是发生过 concurrent edit。

---

# 13. Format transaction

如果 formatted 与原文本相同：

```text
status = unchanged
```

不要产生 transaction。

否则通过一个 CodeMirror transaction 应用整个结果。

同时恢复由 Prettier `formatWithCursor` 计算的新 cursor。

transaction annotations：

```ts
[
  Transaction.userEvent.of("input.format"),
  isolateHistory.of("full"),
]
```

注意：

不要写不存在或未经确认的：

```ts
userEvent: "input.format"
```

CodeMirror transaction metadata 使用 `annotations`。

`isolateHistory.of("full")` 必须存在，确保 Format 自己形成独立 undo history boundary。

完成后：

```ts
view.focus();
```

# 14. Format undo semantics

要求：

```text

↓

↓

```

# 23. Color parsing strategy

不要仅用全文 regex。

利用现有 Lezer CSS syntax tree。

重点识别 CSS declaration value 内的：

```text
ColorLiteral
CallExpression
ValueName
```

使用浏览器：

```ts
CSS.supports("color", candidate)
```

做第二层合法性校验。

支持第一版：

```text
#rgb
#rgba
#rrggbb
#rrggbbaa

rgb()
rgba()

hsl()
hsla()

hwb()

lab()
lch()

oklab()
oklch()

color()

CSS named colors
```

函数识别使用明确的 color-function allowlist，不要把所有 CallExpression 都当颜色。

第一版不要给这些生成 swatch：

```text
var(...)
env(...)
currentColor
inherit
initial
unset
revert
revert-layer
```

它们不是独立可确定的静态色值。

---

# 24. Color syntax traversal

如果一个 `CallExpression` 本身已经被识别为合法 color function：

```text
add one swatch
↓
不要继续扫描内部子节点
```

避免：

```css
rgb(...)
```

产生重复 decorations。

对于非颜色函数：

```css
linear-gradient(red, rgb(...))
```

继续扫描 descendants，使其中 `red` / `rgb()` 能各自产生 swatch。

注意 visible ranges 可能存在多个 range；避免同一个 node 因 range overlap 被重复 decoration，必要时按 document position 做轻量 dedupe。
