# MDX Learning Flow v1 → M6A 衔接约束

## 状态

本文件不是当前 MDX 分支的开发 Task。

只有：

```text
MDX Learning Flow v1
→ 审核通过
→ 合入 main
```

之后，才基于最新 main 修订 M6A 文档。

当前 Codex 完成 Task 06 后必须停止。

---

## 1. M6A 不需要重做总体设计

现有 M6A：

```text
Workspace
Draft
Execution Snapshot
Exercise v2
Progress v2
HTML/CSS Editor
Browser Runtime
Security
```

方向仍成立。

需要做的是把 MDX Learning Flow v1 作为“必须保留的既有产品能力”写入任务约束。

---

## 2. Task 01 后续修订点

M6A Task 01 当前会触及：

```text
src/lib/content/types.ts
src/lib/content/schemas/exercise.ts
preview message/result types
```

修订时必须确认：

- Lesson runtime 不重新引入 MDX body/source。
- MDX registry/source inspector 不被 Exercise v2 设计污染。
- CheckResult neutralization 不应丢失已经验证有教学价值的 diagnostics information。

尤其重新评估：

```text
reason
selector
property
expected
actual
```

哪些属于统一 result，哪些属于 checker-specific detail。

不要简单退回只能表达：

```text
id/message/passed/expected/actual
```

而损失“checker fault vs learner mismatch”的区分能力。

---

## 3. Task 02 后续修订点

M6A Content Assets / Reader cutover 必须明确：

```text
lesson.mdx
不属于 Exercise workspace asset migration
```

保留：

```text
lesson.json
lesson.mdx
generated MDX registry
LessonContentInspector
content:check
```

Exercise v1 → v2 asset migration只处理：

```text
exercise.json
fixture/base/starter/solution
→
workspace starter/solution
```

不得把 Lesson MDX 混入 Workspace。

---

## 4. Task 04 后续修订点

Workspace Editor 重构：

```text
editor-panel.tsx
learning-workspace.tsx
```

时必须保留：

- MDX Lesson panel。
- Activity learning flow。
- progressive hints。
- 当前 exercise context。
- Lesson/Workspace 的产品布局关系。

M6A 可以替换 Editor implementation，但不得把 learner shell 回退到旧三等分大卡片布局。

---

## 5. Task 05 后续修订点

Browser Runtime 会重写：

```text
preview-frame.tsx
preview-document.ts
preview-messages.ts
```

允许彻底替换底层实现。

但必须保留 UI/product contract：

- Preview Panel 可调整。
- bounded canvas。
- Auto / viewport presets。
- Check results 区域。
- structured diagnostics。
- progressive hints 不依赖 runtime internals。

换言之：

```text
PreviewPanel UX contract
= preserve

PreviewFrame/runtime implementation
= replaceable
```

---

## 6. Checker Schema

当前：

```text
StyleCheck.alsoAccepts
```

只视为 transitional compatibility capability。

M6A 不要顺手设计最终 matcher framework。

后续单独 Checker Contract milestone 再考虑：

```ts
matcher:
  equals
  oneOf
  ...
```

以及：

- canonical solution。
- valid alternatives。
- invalid cases。
- check isolation。
- Browser contract tests。

---

## 7. AGENTS / README

M6A 最终 AGENTS 更新时要保留正式 MDX 规则：

```text
lesson.json = metadata
lesson.mdx = teaching content
generated registry = build-time content module lookup
```

同时保持：

- MDX 禁 import/export。
- MDX component whitelist。
- Exercise Activity lesson-local reference。
- content:generate / content:check。

不要让 M6A 的 Workspace 文档覆盖掉 Lesson Content Domain 约束。

---

## 8. M6A 启动前流程

MDX 分支合入 main 后：

```text
最新 main
→ 全量重读 docs/任务计划/00-06 M6A
→ 对照真实代码
→ 只修受 MDX/checker baseline 影响的章节
→ 独立审核更新后的 M6A docs
→ 生成新的 Codex Task 01 执行提示
→ 才正式开发 M6A
```

不要直接拿旧 M6A 提示词开始执行。
