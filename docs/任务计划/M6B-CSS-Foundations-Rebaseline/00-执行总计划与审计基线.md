## 3. 重要审计结论

### 3.1 不直接 merge 旧 curriculum branch

禁止把 feat/css-foundations-v1-curriculum-plan 整体 merge 到新的 implementation branch。

原因：

- 它包含旧 Exercise v1 source contract。
- 它包含旧 authoring Exercise scaffolder。
- 它修改了 AGENTS.md 和 M6A 相关文档，内容落后于正式 main。
- 它的 generated registry 是旧 contract 产物。
- 对重叠的 flexbox-alignment 与 3 个 published Exercise，main 和 curriculum branch 都有有价值但不同的变更。

旧分支作为 read-only source evidence 保留；M6B 从最新 main 新开分支并做选择性 forward-port。

### 3.2 CSS Foundations v1 不需要 editable HTML

课程分支冻结的 learner contract 是：

~~~text
HTML prerequisite: 能阅读基础 HTML / DOM
CSS prerequisite: zero CSS
authoring: fixed HTML + CSS-only
~~~

因此 M6B 不以“首个 editable HTML Exercise”为目标。M6A 已经提供 editable HTML platform capability，但真实 curriculum 没有需求时不应为了证明平台而扩大课程范围。

editable HTML 的正式 learner-route E2E 要求继续保留；当未来真实课程首次启用 editable HTML 时再执行。

### 3.3 不启动 JS/TS Runtime

M6B 禁止：

- JavaScript Worker Runtime。
- JavaScript Browser Runtime。
- TypeScript Toolchain。
- TypeScript type-check workflow。
- RuntimeRegistry / ToolchainRegistry / CheckerRegistry。
- generic IDE / VFS / terminal / npm runtime。

Workspace language vocabulary 中存在 javascript/typescript 不等于当前 runtime 已支持执行。

### 3.4 main 治理缺口

审计时 main：

~~~text
protected = false
repository rulesets = []
~~~

Quality Gate 会运行，但不能阻止直接 push 绕过 PR gate。

这不是 M6A code regression，但属于 release governance 缺口。Task 06 必须形成明确处理结果；如果 GitHub 权限或 plan 阻止配置，不得虚报已启用。

## 4. 必须保护的现有 contract

M6B 不得破坏：

- Exercise revision 作为 progress compatibility boundary。

  - store exercise-progress

  - sandbox=allow-scripts only
  - CSP fail-closed

  - generation/request/source validation

## 9. Final merge rule

M6B 是一个 release unit。

只有 Task 01~06 全部满足、完整 gate 在最终 feature HEAD 真实通过、最新 main drift 已重新评估后，才允许正常 merge workflow 合入 main。

禁止：

- force push。
- rebase 共享历史。
- reset --hard 覆盖远端。
- squash 掩盖迁移阶段事实（除非用户后续明确改变 merge policy）。
- 把旧 curriculum branch 整体 merge 到 main。
- 为通过检查而降低 M6A security/content assertions。
