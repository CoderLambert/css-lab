## 2. 已确定的架构结论

### Content / Schema

- Course / Module / Lesson 继续 `schemaVersion: 1`。
- Exercise 升级为 `schemaVersion: 2`。
- Task 01 只建立 v2 domain/schema definitions，不切生产 ContentReader。
- Task 02 才进行 Exercise v2 + content assets + ContentReader 的原子 cutover。
- `solution/` 永远不进入 learner-facing `Exercise`。
- ContentReader 负责 read + validate + hydrate，不负责 learner published visibility policy。
- canonical `coursesRoot` 安全边界覆盖目录祖先，也覆盖 Reader/Inspector 实际读取的 metadata、Lesson source 与 Workspace asset 最终文件；所有最终文件必须 contained、non-symlink、regular。

### Workspace

Workspace language vocabulary：

```text
html
css
javascript
typescript
```

这表示领域词汇，不表示当前 Runtime 已支持所有语言。

Workspace file：

```ts
{
  path: string;
  language: WorkspaceLanguage;
  editable: boolean;
}
```

规则：

- path 是 POSIX 风格 logical path，不是 OS filesystem path。
- file set 由 content author 声明。
- 允许受控子目录。
- learner 当前不能 create/delete/rename。
- locked file 使用 `editable: false`。
- locked file 不是 secret，不能包含答案。
- Workspace structural schema 允许零 editable file；是否适合作为 Exercise 由 Content Health 判断。
- Browser entry 属于 Runtime Definition，不属于 Workspace Definition。

### Starter / Solution

当前：

```text
fixture.html
base.css
starter.css
solution.css
```

迁移为：

```text
starter/
  index.html
  base.css
  style.css

solution/
  style.css
```

不创建 `support/`。`base.css` 是 locked Workspace file，因为它是真实 execution input。

`solution/` 只包含 editable files 的参考答案，path set 必须与 editable path set 完全相等。

### Learner Draft

Learner Draft：

- 只包含 editable files。
- 不包含 locked files。
- 不包含 solution。
- 不包含 runtime/compiler/console state。
- 不包含 active tab。
- dirty 从 starter + draft 派生，不持久化。

### Execution Snapshot

- 是 Runtime/Checker 的完整不可变输入。
- locked file 使用 starter content。
- editable file 使用 learner draft content。
- 保留 Workspace declaration order。
- Runtime 不知道 editable、Progress、solution 或 OS filesystem path。

### Runtime / Toolchain

- Browser / Worker 是 Runtime。
- TypeScript compiler 是 Toolchain。
- M6A 不添加 `toolchain: null`。
- 不创建 Worker Runtime placeholder。
- 不创建 RuntimeRegistry / ToolchainRegistry。

当前 Browser capability：

```text
HTML + CSS only
```

Workspace schema 可以表达 JavaScript/TypeScript，但：

- Studio Content Health 对当前 Browser exercise 中 JS/TS 报 error。
- 最终 Browser Runtime 对 JS/TS fail closed，绝不执行。
- Task 05 完成前，不向 content 添加 JS/TS workspace files。

### Checker

- style / exists / count 是 Browser DOM checker definitions。
- Check definition 可以 runtime/domain-specific。
- CheckResult 的公共语义保持 runtime-neutral，但必须继续区分 learner mismatch 与 checker/runtime fault，并保留足够 learner diagnostics。
- Browser-specific diagnostics（例如 selector/property）可以通过 Browser result/detail 承载；不要为了 neutralization 删除现有诊断能力。
- M6A Browser DOM checks 只查询 learner fragment 的后代节点；runtime-owned `html/head/body`、learner-root wrapper、CSS slots 与 bridge nodes 永远不是 checker target，也不能污染 `exists/count/style` 结果。
- 当前 `StyleCheck.alsoAccepts` 是 transitional schema，但“一个 check 可接受多个语义等价 computed values”的行为必须保留。
- 不创建 CheckerRegistry，也不在 M6A 引入最终 matcher framework。

## 3. 阶段顺序与事务边界

必须按顺序：

1. Task 01 — Workspace Domain + Exercise v2 definitions
2. Task 02 — Content Assets + Exercise v2 atomic cutover + Studio
3. Task 03 — Progress v2 + IndexedDB migration
4. Task 04 — Workspace Editor + HTML/CSS editor capability
5. Task 05 — Execution Snapshot + Browser Runtime + security
6. Task 06 — Integration + regression + AGENTS/docs

Task 01 完成后：

- 旧 Exercise v1 production flow 仍完整工作。
- 新 Workspace/v2 definitions 已存在。
- 不允许出现“代码只认 v2，但磁盘仍 v1”。

Task 02 完成后：

- content、Exercise runtime type、ContentReader 一次性切 v2。
- CSS Lesson Authoring Skill 同时切到 Exercise v2/starter+solution workspace layout；Task 02 结束后 repo 内不能存在“应用只认 v2、官方 scaffolder 仍生成 v1”的状态。
- 旧 `fixtureHtml/baseCss/starterCss` **不再属于 Exercise runtime domain**。
- 由于 Task 03/04/05 尚未完成，允许一个局部的 Workspace→现有 CSS learner flow compatibility bridge，使旧 Progress/Editor/Preview 在本阶段仍能运行。
- 这个 bridge 必须从 `Exercise.workspace/runtime` 派生，不能把 legacy fields 塞回 Exercise type，也不能形成 v1/v2 双读。
- bridge 的生命周期必须写死：Task 03 去掉 Progress 对 legacy starterCss/code contract 的依赖；Task 04 去掉 Editor 的 CSS-only state；Task 05 删除最后的 legacy Preview adapter。

每阶段建议独立 commit，但只在 Task 06 完成后整体合入 main。

## 4. Release / rollback compatibility

M6A 同时包含两类 forward migration：

```text
Exercise content/schema v1 -> v2
CSS Lesson Authoring Skill scaffold contract v1 -> v2
IndexedDB progress version 1 -> 2
```

因此上线后不能把“直接 git revert 到 M6A 前代码”当作安全 rollback：

- 旧 ContentReader 不理解 Exercise schema v2 / starter workspace layout。
- 已升级到 IndexedDB version 2 的浏览器不能依赖旧 version-1 application code继续正常打开/写入。
- production rollback 必须仍理解 Exercise v2 + Progress DB v2，通常应采用 compatibility hotfix 或 forward-fix。
- 如果需要关闭某项新 UI/Runtime行为，应在 v2-compatible代码上降级，而不是恢复旧 content/storage contract。
- 禁止用 `deleteDatabase` 作为 rollback 或 migration recovery策略。

M6A feature branch 在最终 PR 前可以保留多个阶段 commit，便于 review/bisect；**release unit 仍是完整 M6A**。

## 8. 最终 Definition of Done

- MDX Learning Flow v1 行为无回归：受控 DSL、generated registry、progressive hints、Preview presets、structured diagnostics 与 canonical Exercise sequence 全部保留。
- `pnpm test:authoring-skill`、`pnpm content:check` 与 `pnpm test:content` 在最终状态通过。
- CSS Lesson Authoring Skill 已生成 Exercise v2 + `starter/`/`solution/` layout，active references/AGENTS 不再指导 v1 asset contract。
- 当前 3 个 CSS Exercise 行为无回归。
- Exercise runtime domain 不再有 `fixtureHtml/baseCss/starterCss`。
- Progress runtime contract 不再有 `code: string`。
- Workspace Editor 支持 content-defined editable HTML/CSS files。
- 当前 CSS Exercise 可以继续保持 HTML locked。
- locked HTML/CSS 参与 execution，但不进入 Learner Draft。
- solution 永不进入 learner props/runtime domain。
- Browser Runtime 只消费 Runtime Definition + Execution Snapshot + check request。
- Browser Runtime 对当前 M6A topology fail closed：恰好一个 HTML entry，其他 execution files 只能是 CSS。
- Runtime message protocol 有独立 document generation identity；stale generation 的 ready/update/check/result 全部被拒绝。
- check 执行前明确同步 captured snapshot 对应的最新 CSS，不能依赖 React effect 时序。
- CSS edit 无 iframe reload hot update。
- HTML content change 通过 document rebuild 更新 Runtime。
- learner HTML 不获得任意 JavaScript execution。
- v1 IndexedDB progress 可迁移到 v2。
- FileContentReader 以 canonical `coursesRoot` 为 filesystem trust anchor；从该根到 Course/Module/Lesson/Exercise/starter 的全部后代路径 segment，以及 declared starter file 本身，都必须满足 containment / no-symlink / regular-file 约束，不能只检查 `starter/` 内部、logical path grammar 或 Studio health。
- FileContentReader 与 Lesson/Exercise source inspectors 实际读取的 `course.json/module.json/lesson.json/exercise.json/lesson.mdx` 及 source assets 最终文件同样必须满足 containment / no-symlink / regular-file 约束；不能只保护目录祖先。
- IndexedDB v2 open 被 legacy/non-cooperative connection `blocked` 时，learner hydration 必须有界结束并进入 session-local in-memory fallback；Editor/Preview/Checker/Reset 继续工作，且迟到的 DB open/data 不得覆盖当前 session draft。
- Studio Workspace/source health 的每条新增规则都有负向自动化覆盖，不能只依赖当前三个健康 Exercise 的 happy-path E2E。
- Browser checker selector scope排除 runtime-owned document shell、learner-root wrapper 与 CSS slots，并有 `exists/count/style` 隔离测试。
- M6A release/rollback policy 明确为 forward-compatible，不把直接恢复 v1 reader/storage代码当作安全回滚。
- completed exercise 后续编辑仍保持 completed achievement。
- Studio 能检查 Workspace authoring semantics 和 solution completeness。
- AGENTS.md 更新为 Front-end Lab Platform 长期方向。
- 不提前实现 M6B / JavaScript Runtime / TypeScript Toolchain。
