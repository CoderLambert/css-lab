## 多个候选声明，最后只能有一个 winner

M1 解决的是“哪些规则匹配这个元素”。一旦多个匹配规则都为**同一个 property**提供 declaration，就出现新的问题：浏览器必须决定哪一个 declaration 获胜。

<Concept title="Cascade 决定同一 property 的 winning declaration">
完整 cascade 不只看 specificity。浏览器会先处理规则是否 relevant，以及 origin / importance 等更高层级；只有候选 declaration 仍处在可比较的同一层级时，specificity 才参与比较；如果 specificity 也相同，后出现的 declaration 才通过 source order 获胜。

本课的练习把环境固定在同一 author origin、normal importance、无 cascade layer / scope 的简单场景里，因此重点只观察 specificity 与 source order。
</Concept>

## Specificity 不是 selector 字符数

不要把“后写覆盖前写”当成普遍规则，也不要把 `!important` 当成冲突出现时的默认修复。先找到真正参与竞争的 declarations，再判断 cascade 为什么选中了 winner。
