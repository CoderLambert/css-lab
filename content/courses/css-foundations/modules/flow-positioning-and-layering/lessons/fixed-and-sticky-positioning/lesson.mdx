## fixed 与 sticky 都不是“随便钉在屏幕上”

`fixed` 和 `sticky` 都改变了元素在滚动场景中的表现，但 mental model 不同。先问它是否还保留 normal-flow participation，再问它的 offset 参照哪个 viewport 或 scrollport。

<Concept title="sticky 是 flow participation 加滚动阈值">
`fixed` 通常脱离 normal flow，并以 fixed containing block（常见情形是 viewport）计算 inset；某些祖先的特定 containing-block 建立条件也会改变这个参考上下文。它适合固定控件，但不是“把任何元素变成全局最高层”的声明。

`sticky` 基于 relative positioning：它先在 normal flow 中占位，滚动到指定 inset 阈值后，才在其 scroll container 的范围内表现出粘住的效果；离开约束范围后还会继续受祖先边界限制。因此它需要目标轴上至少一个非 `auto` 的 inset，例如 `top: 0`，还需要有可观察的滚动空间和合适的 scroll context。缺少这些前提时，`position: sticky` 仍是合法声明，却可能看起来完全没有粘住。

不要把 sticky 记成“弱版 fixed”：fixed 的固定参考与 flow participation 不同，sticky 的行为依赖滚动阈值、scrollport 和祖先空间。
</Concept>
