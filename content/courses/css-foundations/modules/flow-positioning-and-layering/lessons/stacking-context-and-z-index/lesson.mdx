## z-index 先问 context，再问数字

当多个 positioned box 重叠时，`z-index` 并不是一张全页面共享的整数排行榜。浏览器先把元素组织进 stacking context hierarchy，再在每个 context 的局部 painting order 中处理它们；一个子 context 会作为一个整体参与父 context 的排序。

<Concept title="stacking context 是局部、原子化的绘制上下文">
同一 stacking context 内，相关项目可以按 `z-index` 和 painting order 比较。常见的 positioned element 搭配非 `auto` 的 `z-index` 可以建立 context，某些 opacity、transform 等视觉效果也可能建立 context；这里学习诊断思路，不背一张穷尽所有 trigger 的清单。

嵌套 context 的关键后果是：子 context 内部的 `z-index: 999999` 只在自己的父 context 内有意义。它不能穿透父 context 的位置，去压过另一个已经位于更高父 context 的 sibling。要修复 overlay，先定位 context hierarchy 和局部 painting order，不要盲目把数字加大。
</Concept>
