## responsive strategy 是一组协作的约束

综合 responsive component 时，不要从“这个设备需要什么 CSS”开始。先检查 available space、intrinsic content 与 min/max constraints；再让 Flexbox/Grid 的自然算法承担能承担的变化；最后只在真实 content/layout break 出现时加入 selective media query。

<Concept title="constraints → flexible layout → selective rule change">
一个可靠的顺序是：先让 surface 和 typography 在 box model 中成立，再用 `max-width`、`min-width`、Flex wrapping 或 Grid tracks 表达可用空间关系。若同一结构在多个空间下仍然自然适应，就不需要增加 breakpoint。

当 nav、cards 或文本 measure 出现明确的结构性断裂，才用一个能解释其原因的 `@media` 条件改变 layout。Breakpoint 是策略中的一小段条件规则，不是按 390、768、1280 各复制一套页面。
</Concept>
