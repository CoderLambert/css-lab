## 综合练习的边界先于具体 property

Capstone 的 HTML 是固定 fixture；你只编辑 CSS。目标不是复制 screenshot 的像素，而是把前面学过的 mental models 组合成一个能解释的实现：先把 surface 和 typography 做成可读的组件，再安排内部 layout，接着处理更宽的 section 约束，最后用 selective responsive rule 和 debugging pass 检查它在 available space 改变时是否仍然合理。

<Concept title="固定 HTML，分阶段建立可解释的 CSS system">
先把问题拆成几个能回看的阶段：

1. surface / typography：确认 color、background、border、font 与 line metrics 不会让内容失去可读性。
2. box / constraints：使用 `box-sizing`、`max-width`、padding 和可接受的 intrinsic measure，避免 rigid width 成为 overflow 根源。
3. internal layout：根据 DOM 关系选择 normal flow、Flexbox 或 Grid；区分 container context、items、tracks 与 alignment。
4. broader layout：让 header、body、actions 之间形成清楚的 spacing 和 source-order 结构。
5. responsive adaptation：先让 constraints 与 flexible layout 自然承担变化，只在真实 content/layout break 时加入一个 selective media query。
6. debugging pass：若结果不对，沿 selector → cascade → resolved value → context → constraint → environment pipeline 回查，而不是继续堆叠规则。

HTML 不可编辑是边界的一部分：它迫使你用已经存在的 DOM 关系解释布局，同时避免 capstone 变成另一个 HTML editor 或 generic IDE。
</Concept>

本练习的 checker 会用 `rule-style` 验证明确的 authored declaration，并用 `viewport-style` 验证 390、768、1280 的指定 computed outcome。它仍不能可靠判断任意 viewport 的完整 geometry、wrapping、paint/occlusion、scroll 状态或多个等价 CSS solution，因此请在 Preview 的固定 presets 中观察同一份 CSS，并记录你选择 breakpoint 的 content/layout 理由。
