## Selector 的结果是一个匹配集合

写 selector 时，先不要问“哪个写法更强”。先问：**这个 selector 会匹配哪些元素？**

<Concept title="Selector 是 matching expression">
CSS selector 描述匹配条件。type selector 按元素类型匹配；class selector 按 class token 匹配；ID selector 按具体 id 值匹配。

符合条件的元素组成 matched element set。规则里的 declarations 只会提供给这个集合中的元素。
</Concept>

在符合规范的 HTML 中，一个 `id` 值应当在文档内唯一；class 则可以被多个元素共享。因此 `.featured` 很自然地表示一组元素，而 `#summary` 通常指向一个特定元素。这里讨论的是**匹配集合**，不是 specificity。

<Predict

  explanation="逗号组成 selector list；元素只要匹配列表中的任意一个 selector，就属于这条规则的匹配集合。"

## 逗号不是 DOM 层级

<Compare
  leftTitle="class selector"
  leftCode=".featured"
  leftMeaning="匹配 class 列表中包含 featured 的元素。"
  rightTitle="selector list"
  rightCode="h3, .featured"
  rightMeaning="匹配 h3，或匹配 .featured；逗号表达并列匹配，不表达父子关系。"
/>

selector 越长不代表越正确。真正的问题是：它是否准确描述了你想要的目标集合。

当前 checker 会在“selector form 本身就是目标”且能公平定义 exact authored form 时，用 `rule-style` 验证 learner stylesheet，再配合 target/non-target 的 computed result 检查匹配边界。selector list 的成员顺序存在语义等价写法，而当前 `rule-style` 不做 selector-list canonical equivalence，所以 `combine-targets` 只验证两个目标与普通元素的最终匹配结果，不把某一个逗号顺序伪装成唯一正确源码。
