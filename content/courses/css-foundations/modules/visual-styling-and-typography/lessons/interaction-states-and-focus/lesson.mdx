## 状态变化会改变 matched rule set

交互状态不是一个永久写进 DOM 的 class。用户指针、键盘或其他输入改变当前状态时，元素可能开始或停止匹配某个 pseudo-class，于是 cascade 重新选择适用的声明。

<Concept title="把 pseudo-class 当作当前状态的选择器">
`:hover` 表示指针正在悬停等符合条件的状态；`:focus` 表示元素当前拥有 focus；`:focus-visible` 是 focus 的一个更有选择性的可见指示状态，浏览器会根据输入方式和用户代理判断决定何时需要明显提示。

`:focus` 不等于“鼠标状态”，`:hover` 也不是一个要复制进 HTML 的 class。状态规则应当与默认样式一起设计：悬停可以改变 surface 或 border，focus indicator 则必须让键盘使用者能看见当前位置。

不要无条件写 `outline: none`。如果要调整默认 focus ring，应在 `:focus-visible` 等状态中提供足够清晰的替代指示；颜色变化本身也不应是唯一的焦点线索。
</Concept>

`rule-style` 可以检查 `.action:hover`、`.action:focus` 与 `.action:focus-visible` 中明确写出的 authored declarations，但 checker 不会主动驱动真实的指针或键盘 modality，也不能证明 paint/occlusion、滚动状态或所有等价视觉结果。因此仍要通过 Preview 的真实指针与 Tab 操作观察状态；这些行为边界不能被静态规则检查冒充覆盖。
